# Subscription access usability review

ใช้เอกสารนี้สำหรับทดสอบ `FULL`, `GRACE` และ `READ_ONLY` กับผู้ใช้จริงก่อนประกาศความครบถ้วน 100%

## ผู้เข้าร่วมขั้นต่ำ

- เจ้าของหอหรือผู้ดูแลหอ 3 คน โดยอย่างน้อย 1 คนใช้งานผ่านโทรศัพท์เป็นหลัก
- ผู้เช่า 3 คน โดยอย่างน้อย 1 คนไม่ถนัดระบบดิจิทัล
- ผู้ดำเนินการทดสอบ 1 คน ซึ่งไม่ใช่ผู้พัฒนาหน้าจอ

## งานที่ให้ทดลอง

### เจ้าของหอ

1. อธิบายจากหน้าจอว่าแพ็กเกจอยู่ในสถานะใดและยังทำอะไรได้บ้าง
2. ค้นหาและเปิดข้อมูลผู้เช่าใน `READ_ONLY`
3. เปิดสัญญา บิล และดาวน์โหลดข้อมูลเดิม
4. พยายามแก้ข้อมูล แล้วอธิบายว่าทำไมจึงแก้ไม่ได้
5. ต่ออายุแพ็กเกจและส่งหลักฐานการชำระ
6. ติดต่อ Super Admin เมื่อพบปัญหา

### ผู้เช่า

1. เปิดดูบิลและสัญญาใน `READ_ONLY`
2. ระบุจากหน้าจอว่าสามารถส่งสลิป แจ้งเรื่อง หรือส่งข้อความได้หรือไม่
3. ค้นหาวิธีติดต่อเจ้าของหอเมื่อ mutation ถูกปิด
4. ออกจากระบบและเข้าสู่ระบบใหม่หลัง session หมดอายุ

## ตัวชี้วัดผ่าน

- Task completion อย่างน้อย 90% โดยไม่มีคำแนะนำจากผู้ดำเนินการ
- ผู้ใช้ทุกคนระบุสถานะ `GRACE` และ `READ_ONLY` ได้ถูกต้อง
- ไม่มีผู้ใช้เข้าใจ network error ว่าเป็นคำสั่งให้ชำระเงิน
- เวลาเฉลี่ยในการหาปุ่มต่ออายุไม่เกิน 30 วินาที
- Critical error เป็นศูนย์ เช่น เข้าใจว่าบันทึกสำเร็จทั้งที่ระบบปิด mutation
- คะแนนความมั่นใจหลังทำงานเฉลี่ยอย่างน้อย 4 จาก 5

## เกณฑ์ปิดงาน

ผล Playwright, accessibility และ responsive checks ต้องผ่านทั้งหมด และ usability review ต้องผ่านตัวชี้วัดด้านบน หากยังไม่มีผู้เข้าร่วมจริง ให้รายงานสถานะสูงสุดเป็น “พร้อมทดสอบผู้ใช้” ไม่ใช่ 100%
