# แผนนำเข้าข้อมูลจริงและ UAT

เอกสารนี้เป็น gate ก่อนเปิด production ข้อมูลจากกระดาษ รูปจริง และผล UAT ยังไม่สามารถสร้างแทนบริษัทได้ เพราะต้องใช้ต้นฉบับ สิทธิ์เผยแพร่ และผู้ทดสอบจริง

## 1. รับและแปลงข้อมูลจากกระดาษ

1. เจ้าของกำหนดผู้อนุมัติข้อมูลหนึ่งคนและส่งเอกสารผ่านพื้นที่เข้ารหัส ห้ามส่งข้อมูลลูกค้าทาง repository
2. ตั้งรหัสเอกสารต้นทาง เช่น `PAPER-001`; สแกน 300 dpi และเก็บต้นฉบับแบบ read-only
3. เจ้าหน้าที่คีย์ข้อมูลลง CMS เป็น Draft พร้อมบันทึกรหัสต้นทางใน working log ภายนอกระบบ
4. ผู้ตรวจคนที่สองเทียบทุกช่องกับกระดาษ โดยเฉพาะชื่อ รุ่น BTU วันที่ โทรศัพท์ และราคา
5. เจ้าของอนุมัติรายการและสิทธิ์เปิดเผยก่อน Publish
6. สุ่มตรวจอย่างน้อย 10% หลังนำเข้า และเก็บผลตรวจโดยไม่แนบข้อมูลส่วนบุคคลใน Git

ทะเบียนนำเข้า (เก็บในระบบเอกสารบริษัท):

| Source ID | ชนิดข้อมูล | จำนวน | ผู้คีย์ | ผู้ตรวจ | สถานะอนุมัติ | วันที่เผยแพร่ |
|---|---|---:|---|---|---|---|
| PAPER-___ | ___ | ___ | ___ | ___ | รอ/ผ่าน/แก้ไข | ___ |

## 2. เปลี่ยนเป็นรูปและข้อมูลจริง

สำหรับแต่ละหน้าให้เจ้าของยืนยัน ชื่อบริษัท ที่อยู่ ช่องทางติดต่อ เวลาทำการ ประวัติ บริการ ยี่ห้อ/รุ่น/สเปกสินค้า ผลงาน ข่าว และ SEO ลบ placeholder ทั้งหมดก่อน release

ทะเบียนสื่อควรมีชื่อไฟล์ เจ้าของลิขสิทธิ์ หนังสือยินยอม วันที่หมดสิทธิ์ alt text และหน้าที่ใช้งาน ห้ามเผยแพร่ใบหน้า ป้ายทะเบียน ชื่อลูกค้า หรือสถานที่ละเอียดโดยไม่มีฐานสิทธิ์ ลบ EXIF/GPS และตรวจ crop บนมือถือก่อน Publish

## 3. UAT บุคคลทั่วไป 30 คน

คัดเลือกหลายช่วงอายุและอุปกรณ์ โดยไม่เก็บข้อมูลส่วนบุคคลเกินจำเป็น งานทดสอบหลัก:

- หาเบอร์โทร/LINE/แผนที่และกดติดต่อ
- ค้นหาบริการ สินค้าตามรุ่น/BTU และเปิด PDF
- เปิดผลงานและข่าว แชร์ลิงก์ และใช้งานบนมือถือ
- ทดลอง keyboard navigation, zoom 200% และ screen reader อย่างน้อยบางกลุ่ม

เกณฑ์ผ่าน: ผู้ทดสอบอย่างน้อย 27/30 ทำ critical tasks สำเร็จ, ไม่มี blocker/critical defect, task success รวม ≥90%, คะแนนความพึงพอใจเฉลี่ย ≥4/5

## 4. UAT เจ้าของ/พนักงาน 5 คน

ต้องมีอย่างน้อยเจ้าของ/Super Admin 1 คนและ Editor 2 คน ทดสอบ login+2FA, recovery code, สร้าง/แก้/preview/publish/unpublish, รูป/PDF, trash/restore, บัญชี/บทบาท, audit และ forced password reset

เกณฑ์ผ่าน: critical CMS workflows ผ่าน 100%, role isolation ผ่าน, last-Super-Admin protection ผ่าน และไม่มีข้อมูล Draft/Trash รั่วสู่ public

## 5. บันทึก defect และ sign-off

| UAT ID | กลุ่ม | ขั้นตอน | Expected | Actual | Severity | หลักฐาน | Owner | สถานะ |
|---|---|---|---|---|---|---|---|---|
| UAT-___ | Public/Staff | ___ | ___ | ___ | Critical/High/Medium/Low | ___ | ___ | Open/Retest/Closed |

แก้ Critical/High ทั้งหมดก่อน go-live; Medium ต้องมีเจ้าของและกำหนดส่ง; Low อาจยอมรับโดยผู้อนุมัติ ทุก fix ต้องผ่าน regression test และ retest โดยผู้รายงานหรือผู้แทน จากนั้นเจ้าของบริษัทลงชื่อรับรอง version/tag, วันที่, รายการ known issues และผล backup/restore drill

- [ ] Staff UAT 5 คนครบและถึงเกณฑ์
