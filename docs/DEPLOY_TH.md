# การนำ Nestly ขึ้นออนไลน์

เอกสารนี้พาตั้งระบบให้ทำงานครบทุกฟีเจอร์และเก็บข้อมูลไว้ถาวร ผู้ที่เข้ามาใช้เพียงเปิด URL
ไม่ต้องติดตั้งหรือรันอะไรบนเครื่องตัวเอง

## ทำไมไม่ใช้ Vercel

ระบบสร้าง PDF สัญญาและใบแจ้งหนี้ด้วย Puppeteer ซึ่งต้องเปิด Chromium จริง รันบน serverless
ของ Vercel ไม่ได้โดยไม่แก้โค้ด ส่วน `Dockerfile` ของโปรเจกต์ลง Chromium และตั้ง
`PUPPETEER_EXECUTABLE_PATH` ไว้ให้แล้ว แพลตฟอร์มที่รับ Dockerfile จึงใช้ได้ทันที

## ส่วนประกอบ

| ส่วน | บริการที่ใช้ | หมายเหตุ |
| --- | --- | --- |
| ตัวเว็บ | Render (Web Service แบบ Docker) | มี `render.yaml` ให้แล้ว |
| ฐานข้อมูล | Neon (PostgreSQL) | ข้อมูลอยู่ถาวร ไม่หายตอน deploy ใหม่ |
| ไฟล์อัปโหลด | Cloudflare R2 | สลิป รูปพัสดุ ไฟล์แนบแชท และ PDF สัญญา |
| อีเมล | Resend | ใช้กับการรีเซ็ตรหัสผ่าน |
| งานตามเวลา | ตัวตั้งเวลาภายนอก เช่น cron-job.org | เรียก endpoint งานเบื้องหลัง |

Render แผนฟรีจะพักเครื่องเมื่อไม่มีคนใช้ราว 15 นาที ผู้เข้าชมคนแรกจึงต้องรอราวหนึ่งนาที
ถ้าไม่ต้องการจังหวะนี้ให้เปลี่ยนเป็นแผนที่เสียเงิน หรือใช้ Railway หรือ Fly.io ซึ่งใช้
`Dockerfile` ตัวเดียวกันได้

## ขั้นตอน

### 1. ฐานข้อมูล

สร้าง project บน Neon แล้วคัดลอก connection string เก็บไว้ ใช้เป็นค่า `DATABASE_URL`

### 2. ที่เก็บไฟล์

สร้าง bucket บน Cloudflare R2 แล้วสร้าง API token แบบอ่านและเขียน จะได้ค่าสี่ตัว

| ค่า | ที่มา |
| --- | --- |
| `AWS_S3_BUCKET` | ชื่อ bucket |
| `AWS_S3_ENDPOINT` | `https://<account_id>.r2.cloudflarestorage.com` |
| `AWS_ACCESS_KEY_ID` | จาก API token |
| `AWS_SECRET_ACCESS_KEY` | จาก API token |

ตั้ง `AWS_REGION` เป็น `auto` และ `STORAGE_TYPE` เป็น `s3`

> R2 เข้ารหัสไฟล์ตอนเก็บให้เองอยู่แล้ว โค้ดจึงไม่ส่ง header เข้ารหัสของ AWS ไปให้
> ถ้าเปลี่ยนไปใช้ AWS S3 ตัวจริงให้เว้น `AWS_S3_ENDPOINT` ว่างไว้ ระบบจะส่ง header นั้นเอง

### 3. อีเมล

สมัคร Resend แล้วสร้าง API key แบบ sending access

- `RESEND_API_KEY` คือ key ที่ได้
- `PASSWORD_RESET_EMAIL_FROM` ตั้งเป็น `Nestly <onboarding@resend.dev>` ถ้ายังไม่มีโดเมน

**ข้อจำกัดเมื่อใช้ผู้ส่ง `onboarding@resend.dev`** ส่งได้เฉพาะไปยังอีเมลที่ยืนยันไว้กับ Resend
เท่านั้น พอสำหรับสาธิตว่าฟีเจอร์ทำงาน แต่คนอื่นกดลืมรหัสผ่านแล้วจะไม่ได้รับเมล
ถ้าต้องการส่งหาใครก็ได้ ต้องเพิ่มโดเมนของตัวเองใน Resend แล้วตั้งค่า DNS ตามที่ระบบบอก

ถ้าไม่ตั้งค่าสองตัวนี้ ฟีเจอร์ลืมรหัสผ่านจะตอบ 503 ส่วนฟีเจอร์อื่นทำงานปกติ

### 4. สร้างบริการบน Render

1. push โค้ดขึ้น GitHub
2. Render → **New** → **Blueprint** → เลือก repository นี้ Render จะอ่าน `render.yaml` เอง
3. กรอกค่าที่ขึ้นว่าต้องใส่เอง ได้แก่ `DATABASE_URL`, `APP_URL`, ค่าของ R2, ค่าของ Resend
   และบัญชีชุดแรกในข้อถัดไป
4. `APP_URL` ใส่ URL ที่ Render ให้มา เช่น `https://nestly.onrender.com`

`JOB_SECRET` Render จะสุ่มให้เอง ไปคัดลอกจากหน้า Environment เมื่อถึงข้อ 6

### 5. เตรียมฐานข้อมูลและบัญชี

สามคำสั่งนี้รันครั้งเดียวจากเครื่องที่มีโค้ดอยู่ โดยชี้ `DATABASE_URL` ไปที่ Neon
เป็นการตั้งค่าครั้งแรกเท่านั้น ผู้ที่เข้ามาใช้ระบบไม่ต้องรันอะไร

```bash
export DATABASE_URL="<connection string ของ Neon>"

# สร้างตารางทั้งหมด
npx prisma migrate deploy

# สร้างบัญชีผู้ดูแลระบบและเจ้าของหอ
export BOOTSTRAP_ADMIN_EMAIL="owner@example.com"
export BOOTSTRAP_ADMIN_PASSWORD="<อย่างน้อย 12 ตัว>"
export DEMO_PROPERTY_ADMIN_EMAIL="admin@example.com"
export DEMO_PROPERTY_ADMIN_PASSWORD="<อย่างน้อย 12 ตัว>"
npm run admin:bootstrap

# เติมข้อมูลตัวอย่าง หอ 10 ห้อง ผู้เช่า 3 คน บิลย้อนหลัง 3 เดือน พัสดุ แจ้งซ่อม ประกาศ
export DEMO_TENANT_PASSWORD="<อย่างน้อย 12 ตัว>"
npm run seed:demo
```

`seed:demo` รันซ้ำได้เสมอ ทุกคำสั่งเป็นการเขียนทับของเดิม ไม่สร้างข้อมูลซ้ำ

ข้อมูลที่ได้ประกอบด้วยแพ็กเกจที่ยังไม่หมดอายุ ถ้าไม่มีส่วนนี้พื้นที่เจ้าของหอจะกลายเป็น
โหมดอ่านอย่างเดียวและกดปุ่มอะไรไม่ได้เลย

### 6. งานเบื้องหลังตามเวลา (ไม่บังคับ)

ระบบมีงานลบไฟล์ที่พ้นระยะเก็บและงานดูแลข้อมูลตามรอบ เรียกผ่าน endpoint นี้

```
POST https://<โดเมนของคุณ>/api/internal/jobs/maintenance
Authorization: Bearer <JOB_SECRET>
```

มีสองทางเลือก

- **ตัวตั้งเวลาภายนอกแบบฟรี** เช่น cron-job.org ตั้งให้ยิงวันละครั้งพร้อม header `Authorization`
  ข้างบน เป็นทางที่ไม่มีค่าใช้จ่าย
- **Cron Job ของ Render** สะดวกกว่าเพราะอยู่ที่เดียวกัน แต่เป็นบริการที่ต้องเสียเงิน
  ไม่มีในแผนฟรี

ถ้าไม่ตั้งส่วนนี้ ระบบยังใช้งานได้ปกติ เพียงแต่ไฟล์ที่พ้นระยะเก็บจะไม่ถูกลบตามกำหนด

## หลัง deploy ควรตรวจอะไรบ้าง

| ตรวจ | วิธี |
| --- | --- |
| ระบบขึ้นแล้ว | เปิด `/api/health` ต้องได้ `{"status":"ok"}` |
| ฐานข้อมูลต่อติด | ข้อเดียวกัน เพราะ endpoint นี้ยิงคำสั่งไปที่ฐานข้อมูลจริง |
| เข้าระบบได้ | ล็อกอินด้วยบัญชีเจ้าของหอ ต้องเห็นหอพักทดลองพร้อมข้อมูล |
| แพ็กเกจใช้งานได้ | ปุ่มเพิ่มและแก้ไขในพื้นที่เจ้าของหอต้องกดได้ ไม่ขึ้นป้ายโหมดอ่านอย่างเดียว |
| อัปโหลดไฟล์ | แนบรูปในเรื่องแจ้งซ่อม แล้ว deploy ใหม่ ไฟล์ต้องยังเปิดได้ |
| สร้าง PDF | เปิดดูตัวอย่างสัญญาหรือใบแจ้งหนี้ ต้องได้ไฟล์ PDF ไม่ใช่ข้อความผิดพลาด |

## ข้อควรรู้

**การ์ดบัญชีทดลองจะไม่ขึ้นบนหน้าเข้าสู่ระบบ** เพราะโค้ดบังคับให้แสดงเฉพาะตอนที่ไม่ใช่
production ซึ่งถูกต้องแล้ว เว็บสาธารณะไม่ควรโชว์รหัสผ่าน ให้ส่งบัญชีสำหรับเข้าทดสอบ
ไปพร้อมงานแทน

**บัญชีที่ seed สร้างไว้**

| บทบาท | อีเมล | รหัสผ่าน |
| --- | --- | --- |
| ผู้ดูแลระบบ | ค่าใน `BOOTSTRAP_ADMIN_EMAIL` | ค่าใน `BOOTSTRAP_ADMIN_PASSWORD` |
| เจ้าของหอ | ค่าใน `DEMO_PROPERTY_ADMIN_EMAIL` | ค่าใน `DEMO_PROPERTY_ADMIN_PASSWORD` |
| ผู้เช่าหลัก ห้อง 101 | `somchai@nestly.demo` | ค่าใน `DEMO_TENANT_PASSWORD` |
| ผู้พักร่วม ห้อง 101 | `suda@nestly.demo` | ค่าเดียวกัน |
| ผู้เช่าหลัก ห้อง 202 | `wichai@nestly.demo` | ค่าเดียวกัน |

**อย่า commit ค่าจริง** ทุกค่าตั้งผ่านหน้า Environment ของ Render เท่านั้น
ไฟล์ `render.yaml` ตั้ง `sync: false` ไว้กับทุกค่าที่เป็นความลับอยู่แล้ว

## ย้อนกลับเมื่อมีปัญหา

- **โค้ดมีปัญหา** Render เก็บ deploy เก่าไว้ กด Rollback ได้จากหน้า Deploys
- **ฐานข้อมูลมีปัญหา** Neon มี point-in-time restore ย้อนไปยังเวลาก่อนหน้าได้
- **migration ผิด** ห้ามแก้ไฟล์ migration ที่ deploy ไปแล้ว ให้เขียน migration ใหม่ทับ
  แล้วรัน `npx prisma migrate deploy` อีกครั้ง
